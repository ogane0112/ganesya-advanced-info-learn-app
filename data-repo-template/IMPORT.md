# 過去問の取り込みルール

IPA 公式の PDF(`ipa-pdf/<年度>-<期>/` の `qs.pdf` 問題冊子 / `ans.pdf` 解答例 / `cmnt.pdf` 採点講評)を
アプリ用の問題ファイル `questions/<年度>-<期>/qNN.md` に変換する。
PDF が無ければ先に `node scripts/fetch-ipa.mjs --year <年度> --season <spring|autumn>` で取得する。

## 手順

1. 読み取り
   - テキスト: `pdftotext -layout ipa-pdf/<回>/qs.pdf -`(`-f <頁> -l <頁>` で頁指定)。解答例・採点講評も同様
   - 図や表の見た目、文字化けの確認は Read ツールで PDF を直接見る
2. 問ごと(指示がなければ問1〜問11すべて)に `questions/<年度>-<期>/qNN.md` を作る(`q01`〜`q11`)
   - **既存ファイルは上書きしない。** 例外は frontmatter に `sample: true` があるファイル(上書きしてよい)
3. `node scripts/check-questions.mjs questions/<年度>-<期>` を実行し、error が 0 になるまで直す。warn は確認して、妥当なら残してよい
4. 1回分(1つの年度・期)ごとに1コミット: `import: <年度>-<期> 問1〜問11`
   (画像も同じコミットに含める。`ipa-pdf/` は commit しない)
5. `git pull --rebase origin main` してから `git push origin HEAD:main`

## ファイル形式

```markdown
---
year: 2024
season: spring
number: 3
field: プログラミング
title: "マージソート"
---
## 本文

(問題文)

## 設問
```yaml
- id: "1-a"
  text: "..."
  type: fill
  points: 2
  answer: "..."
```
```

### frontmatter
- `field`: 問題冊子の表紙にある出題分野の名称を使う。見つからなければ次の対応で:
  問1 情報セキュリティ / 問2 経営戦略 / 問3 プログラミング / 問4 システムアーキテクチャ / 問5 ネットワーク /
  問6 データベース / 問7 組込みシステム開発 / 問8 情報システム開発 / 問9 プロジェクトマネジメント /
  問10 サービスマネジメント / 問11 システム監査
- `title`: 問題文冒頭「〜に関する次の記述を読んで」の「〜」部分(例: 「マージソート」)
- 出典は年度・期・問番号から画面に自動表示されるので `source` は書かない

### 本文
- 問題冊子の文章を **一字一句そのまま** 写す。要約・言い換え・省略をしない。設問より前の部分すべて
- 〔 〕付きの小見出しは `**〔…〕**` の段落にする
- 表は Markdown の表にする(セル結合は近い形で表現し、無理なら画像)
- プログラム・擬似言語は ``` のコードブロックにする(字下げを保つ)
- 空欄は `[ a ]` `[ ア ]` のように書く(問題冊子の記号のまま)
- 下線①などの記号もそのまま残す
- 図(構成図・状態遷移図・E-R 図など)は画像にする:
  `pdftoppm -png -r 150 -f <頁> -l <頁> ipa-pdf/<回>/qs.pdf questions/<年度>-<期>/img/qNN-p<頁>`
  で頁を画像化し、本文の該当位置に `![図1 ネットワーク構成](img/qNN-p<頁>-<頁>.png)` のように置く
  (pdftoppm が付ける連番付きの実ファイル名に合わせること。ファイル名は英数字・`-`・`_`・`.` のみ)。
  頁全体の画像なので、図の直前に「(図1は下の画像を参照)」と書き添える

### 設問
- 設問番号の対応: 「設問1 (1)」→ `"1-(1)"`、設問1の空欄 a →`"1-a"`、「設問2」→ `"2"`、
  「設問3 (2) の下線②」→ `"3-(2)"`。同じ設問内で複数の解答欄があれば `"1-(1)-a"` のように分ける。**解答欄1つにつき1項目**
- `text`: 設問文をそのまま。解答群(ア〜エ等)があれば `text` に含める(Markdown のリスト)。
  空欄を問う設問で、設問文が複数空欄共通なら各項目に同じ設問文を入れ、末尾に「(空欄 a)」と添える
- `type`:
  - `fill` … 記号選択・空欄に字句を入れる・用語を答える
  - `numeric` … 数値・計算結果を答える
  - `short` … 「〜字以内で述べよ / 答えよ」の記述
- `limit`: 「〜字以内」の数値(記述のみ)
- `answer`: 解答例 PDF の記載どおり。解答例が複数並記されていれば最初を `answer`、残りを `alt_answers` に
- `points`: IPA は配点を公表していないので推定する。1問の合計を **20 点** にし、記述 > 字句 > 記号 の順で重く
- `notes`: 採点講評のうち、その設問に触れている内容を要約(1〜3文)。講評で触れていない設問は省略してよい
- YAML は必ずダブルクォートで文字列を囲む(`:` や `#` を含むことが多いため)
